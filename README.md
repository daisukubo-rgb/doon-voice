# DOON Voice

話した内容を端末内で文字にして、カーソルがある入力欄へ直接入力するデスクトップアプリです。「AIなし」で音声認識だけを使うことも、選んだAIで文章を整えることもできます。DOON Voice自身は音声入力の履歴を保存せず、辞書やアプリ設定を端末内に保存します。

このリポジトリはDOON Voiceだけで完結しています。ほかのDOONプロジェクトを一緒に取得する必要はありません。

## GitHubから起動する

ソースから起動する場合、macOSの署名やWindowsの証明書は不要です。利用者のPC上でアプリをビルドします。

GitHub ReleasesのAssetsにある `Source code (zip)` を取得し、先に中身をすべて展開してください。展開したフォルダを開き、OSに合うファイルをダブルクリックします。

- macOS: `DOON Voiceを起動.command`
- Windows: `DOON Voiceを起動.bat`

初回は環境確認とセットアップを行ってからDOON Voiceを起動します。2回目以降は、使用する部品に変更がなければセットアップを飛ばして起動します。Node.jsが入っていない場合はダウンロードページを開きます。Rustなどが不足している場合は、画面に準備内容を表示して停止します。Node.jsやRustなどを一括で自動導入する機能はありません。

ソース版はアプリ内更新の対象外です。更新する場合は新しいソースを取得してください。完成版インストーラーで入れたDOON Voiceは、`接続と設定` の `アプリの更新` → `更新を確認` から公開済みの最新版を確認して適用できます。

ターミナルから起動する場合は、次のコマンドを使います。

```bash
git clone https://github.com/daisukubo-rgb/doon-voice.git
cd doon-voice
npm run setup
npm run app
```

`npm run setup` はNode.js 22以上、Rust、OSごとのビルド・表示環境を確認し、npmの依存関係をインストールします。確認だけ行う場合は `npm run doctor` を使います。

### 必要な環境

- macOS 12以降（Apple Silicon / Intel）: Xcode Command Line Tools、Node.js 22以上、Rust
- Windows 10/11（64ビット）: Node.js 22以上、Rust、Visual Studio Build Tools（C++）、WebView2

WindowsではRustの導入後に、Visual Studio Installerで「Desktop development with C++」を有効にしてください。

## 完成版インストーラーを使う

### Windowsテスト版 0.5.43

配布用の `DOON Voice-Windows.zip` をすべて展開し、中の `.msi` を実行してください。対象はWindows 10/11の64ビット（x64）です。アプリの利用にNode.jsやRustの開発環境は不要です。

CPUに合わせて高速な音声エンジンを自動選択します。AVX2等に対応しない古いCPUでは互換エンジンを使うため、認識に時間がかかり、5分の制限で終了する場合があります。

1. DOON Voiceを起動し、「接続と設定」で「マイクを許可・確認」を押します。表示されたOSの確認画面で許可し、表示が「接続確認済み」になることを確認します。
2. 同じ画面で音声認識モデル（約574MB）を取得します。取得済み容量・全容量・進捗・残り時間の目安を確認できます。
3. Windowsで許可画面が出ない、または以前に拒否した場合は、「設定」で「マイク」を検索し、マイクと「デスクトップアプリにマイクへのアクセスを許可する」をオンにします。
4. 接続確認に失敗した場合は、マイクをつなぎ直すか、OSのサウンド設定で使用する入力を選び直します。Windowsでは「デスクトップ アプリにマイクへのアクセスを許可する」もオンにします。v0.5.39以降は既定マイクのほか、利用できる別の入力機器・音声形式も自動で試します。内蔵マイクで反応しない場合は、イヤホンや外付けマイクを接続して入力先を選び直すと、PC側の入力不良を切り分けられます。
5. 「AIなし」を選び、メモ帳などの入力欄で`Ctrl+Alt+Space`を押して録音し、もう一度押して止めます。
6. 認識した言葉、待ち時間、入力先への貼り付けを確認してください。終了は通知領域のDOON Voiceアイコンから選べます。

ChatGPT／Claude／Geminiの文章整形は、相手自身の対応CLIとログインが必要です。`AIなし`での録音・文字起こしにはこれらのログインは不要です。クラウドAIを選ぶと本文と辞書が対応サービスへ送られます。

コード署名証明書は付けていないテスト版です。Windowsや組織の設定で警告・起動制限が出た場合は、画面の文言を配布元へ知らせてください。Windows ARMネイティブ版と32ビット版は含みません。

開発用のWindowsビルドはGitHub Actionsの `DOON Voice Windows Test Installer` から実行できます。品質検査・実モデル認識・MSI内部検査に成功した場合だけ、手順付きZIPを30日間のartifactとして保存します。一般公開Releaseは別の手順です。

### 一般公開版

GitHubの [Releases](https://github.com/daisukubo-rgb/doon-voice/releases) からOSに合うファイルを取得します。

- macOS Apple Silicon: `DOON.Voice-macOS.zip` を展開し、中の `.dmg` を開きます。
- macOS Intel: `DOON.Voice-macOS-Intel.zip` を展開し、中の `.dmg` を開きます。
- Windows: `DOON.Voice-Windows.zip` を展開し、中の `.msi` を実行します。

GitHub Releasesには、各インストーラーを入れたZIPも添付します。ZIPを展開し、中のDMG（macOS）またはMSI（Windows）をダブルクリックしてください。配布ZIPには、Capsuleで開ける `README.capsule`、ブラウザ用の `README.html`、プライバシー説明、OSS表示と `licenses` フォルダも同梱しています。

初回起動後、`接続と設定` の `マイクを許可・確認` を押してOSの確認画面で許可し、DOON Voice専用の高精度音声認識モデル（約574MB）を取得してください。取得中は容量、進捗、残り時間の目安を表示します。確認結果が「接続確認済み」になれば、OSの許可だけでなく実際の録音経路も使えます。入力先にカーソルを置いて開始・停止キーを押すと、完成した文章がその入力欄へ直接入り、同時にクリップボードにも保存されます。

macOSでは「カーソル位置へ入力」の `許可する` を押し、システム設定のアクセシビリティで、現在 `Applications/DOON Voice.app` に置いたDOON Voiceをオンにしてください。マイクとアクセシビリティの許可はPCごとに必要です。同名のDOON Voiceが2つ表示される場合は、古い方を `−` で削除してから現在のアプリをオンにし、DOON Voiceを再起動してください。macOSの仕様上、この許可をアプリから自動で付与することはできません。

ショートカット操作中は、ほかのアプリより手前に `聞いています`、`考えています`、`入力しました` の状態を表示します。DOON Voiceを最小化していてもショートカットは有効です。

初期ショートカットは `Ctrl+Alt+Space` です。ウィンドウを閉じた後は、メニューバー（macOS）または通知領域（Windows）のDOON Voiceアイコンから `DOON Voiceを開く` を選べます。`DOON Voiceを終了` で終了します。録音・処理中は画面が開くので、停止または処理完了後に終了してください。結果が未コピーでも、待機中なら終了できます。

完成版インストーラーで入れたv0.5.39以降は、`接続と設定` の `アプリの更新` に現在の版と確認結果を表示します。`更新を確認` を押すと、GitHub Releaseの最新版を取得して適用します。通常はアプリを削除せずに更新でき、同じアプリとしてOSが扱うためマイクなどの許可も維持されます。OSが再確認を求めたときだけ、表示された許可画面で承認してください。

## 文章を整えるAIを選ぶ

「文章の仕上げ」で「AIなし」を選ぶと、文字起こしした原文をそのまま使えます。AIアカウントやローカルAIモデルは不要です。音声認識モデルは必要です。

`接続と設定` では、**文章を整えるAI** と **選択文・画面を質問するAI** を別々に選べます。文章を整えるAIは、通信せずに扱える「このPCのAI（Gemma 4 E2B）」がおすすめです。選択文や前面の画面の意味確認、会社・用語の調査、最新情報を尋ねるときは、ChatGPT、Claude、GeminiなどのクラウドAIがおすすめです。どちらの選択も保存され、選択文・画面を質問するキーから実行した場合にも質問用のAIが使われます。

AIで整える場合は次の準備が必要です。DOON Voiceは認証情報の入力欄を持たず、ログインはPCに入れた対応CLIとブラウザーで行います。

| 選ぶAI | 必要な準備 | 使用モデル |
| --- | --- | --- |
| ChatGPT | Codex CLIとChatGPTアカウント | GPT-5.6 Luna（高速整形） |
| Claude | Claude CodeとClaudeアカウント | Claude Haiku（高速整形） |
| Gemini | Antigravityの `agy` CLIと利用可能なGoogleアカウント | Gemini 3.6 Flash (Low) |
| このPCのAI | サインアップ不要のローカルAI実行環境 | Gemma 4 E2B（DOON Voice専用・ローカル処理） |

接続と設定の `ログインする` から対応CLIのログインを始めます。CLIが未導入の場合は、案内に従って先に準備してください。ローカルAIを使う場合は `サインアップ不要でローカルAIを準備`、続けて `Gemmaを取得` を選びます。WindowsではOllama公式のスタンドアロンCLIをDOON Voice専用フォルダーに準備するため、Gemma 4 E2Bの取得・利用にOllamaアカウントは必要ありません。ローカルモデル（約7.2GB）は初回だけ取得し、取得済み容量・全容量・進捗・残り時間の目安を表示します。配布物には含めません。なお、Ollamaのクラウドモデルを利用する場合だけは、Ollama側のアカウントが必要です。

選択中のAIはホーム画面上部と「文章の仕上げ」の両方に表示されます。`接続可能`（CLI検出）、`接続中`、`接続済み`、`選択中`、`稼働中` を区別して表示します。

マイク準備・録音・処理中はAIを変更できません。変更は処理が終わってから行ってください。文字起こしの原文は、文頭の「あー」「えーと」なども含めて保持します。

AIでの処理に失敗しても、文字起こしが完了していればホームの `原文をコピー` で回収できます。`再試行` は選択中のAIで文章を整え直します。コピー後も結果は画面に残り、`破棄` で消去できます。別のクラウドAIへの自動切り替えは行いません。

AIは「あー」「えっと」「あと」など意味を足さない話し言葉、重複、言い直しを除き、話した内容を相手へそのまま渡せる完成文章に書き換えます。同じ内容の繰り返しは一度にまとめ、文脈と辞書を使って助詞・語尾・同音異義語・漢字・固有名詞を確信できる範囲で直します。自然な位置に句読点を入れ、数字・符号・否定・視点・URLやメールアドレスに変化がある場合は原文を使います。流れが大切な内容は段落と改行を使い、独立した項目・手順・比較・依頼を並べる方が伝わりやすい内容は、箇条書きまたは番号付きリストに整えます。番号・ハイフン・中黒は、内容に合う形式をAIが選びます。

ホームの `選択した文章・画面を質問` は、文章を選択していれば選択文を、選択がなければ前面の画面を読み取ります。アクセシビリティを許可済みなら選択文を自動で取得します。画面を読む初回だけはOSの画面収録許可が必要です。質問用キーでも同じ動作になり、画面または選択文を取り込んでから話した質問に回答します。回答は専用ポップアップに表示され、`回答をコピー` で利用できます。質問の本文と選択文または画面画像は、質問用に選んだAIへ送ります。AIなしでは質問に答えられません。

マイク切断や処理中止などで途中までの文章が得られた場合は、確認してからコピーできます。この文章は再試行しても自動で貼り付けません。エラー結果をコピーまたは破棄しなくても、次の録音や選択文質問をすぐに始められます。次の録音を始めると前回の結果は置き換わり、画面の結果はアプリ終了時に失われます。

## プライバシー

- 認証トークン、メールアドレス、パスワード、APIキーをDOON Voiceは読み取り・保存しません。
- 音声認識は端末内で行います。録音一時ファイルは成功・エラー時に削除し、次回起動時にも期限切れファイルを回収します。強制終了などで一時的に残ることがあります。
- 「AIなし」では、文字起こしした本文と辞書をAIへ送信しません。
- ChatGPT / Claude / Geminiを選んだ場合、整形する本文と登録辞書、画面を質問するときは質問用に取り込んだ画面画像を各対応CLIへ渡します。CLI側の設定・履歴・送信後の保存は、利用者の設定と各提供者の仕組みに従います。
- ローカルAIを選んだ場合は `127.0.0.1` のOllamaだけに本文と辞書、質問用に取り込んだ画面画像を渡します。

詳細は [プライバシーの扱い](docs/PRIVACY.md)、[利用条件](docs/TERMS.md)、[OSS表示](docs/OSS-NOTICES.md) を確認してください。

## 開発と配布

```bash
npm ci
npm run build          # フロントエンドの型チェックとビルド
npm test               # 音声・画面・実セットアップ・梱包の回帰テスト
npx playwright install chromium # 画面検証用ブラウザーを準備
npm run test:ui        # 実App＋模擬IPCの画面操作テスト
node scripts/check-licenses.mjs # ロックファイルと同梱ライセンスの照合
npm run dist           # このPC向けのインストーラーを生成
npm run package:zip    # 生成済みインストーラーをZIPで包む
scripts/test-desktop-distribution.sh
```

`v0.5.15` のようなタグをGitHubへpushすると、そのタグのコミットを検査します。macOS・Windowsのテスト、ビルドとインストーラー内のライセンス検査がすべて成功してから、DMG・MSI・ZIPを公開Releaseへ添付します。手動実行も既存タグを対象にし、タグとアプリのバージョンが一致しなければ停止します。ZIPは現バージョンと対象機種に一致するインストーラーが1つだけある場合に生成します。

Google Driveの配布フォルダは、ルート直下を次の3フォルダだけに保ちます。新しい版を公開したら、直前の最新版一式をバージョン別フォルダへ移し、新しい3種類のZIPだけを最新版へ置きます。自動更新用ファイルも最新版と過去を混在させません。

- `01_最新版（vX.Y.Z）`: macOS、macOS Intel、Windowsの配布ZIP
- `02_過去バージョン/vX.Y.Z`: 以前の配布ZIPと当時の手順書
- `03_自動更新用/最新版（vX.Y.Z）`: 現行版の署名付き更新ファイル
- `03_自動更新用/過去/vX.Y.Z`: 以前の更新ファイル

Releaseのファイルを1つの作業フォルダへ取得した後、`DOON_VOICE_DRIVE_ROOT`へDOON VOICEフォルダの場所を指定して `npm run publish:drive -- <作業フォルダ> <version>` を実行します。この処理が直前の最新版を過去へ移し、新しい配布ZIPと署名付き更新ファイルを所定の場所へ保存します。

依存を更新した場合は `node scripts/collect-licenses.mjs` で原文と一覧を再収録し、[OSS表示](docs/OSS-NOTICES.md) の確認事項も見直してください。公開前には各OSで実マイク、直接入力、AI接続を確認してください。

ソースリポジトリの共有・各自ビルドに配布用の署名証明書は不要です。macOSは証明書不要のローカル署名（ad-hoc）でアプリの整合性を保ちます。開発元を証明するDeveloper ID署名・Apple公証、Windowsのコード署名は設定していないため、OSの警告や組織のポリシーで起動が制限される場合があります。配布元を確認し、OSの案内に従ってください。
